# SPW-Listen Stats 插件说明

SPW-Listen Stats 是 Salt Player for Windows 的本地听歌统计模组。它在播放器页面中显示听歌概览、热力图、时长分布、歌曲明细，以及歌曲、歌手和专辑排行。

这是一份面向普通使用者的说明，介绍插件的用途、安装、数据来源、备份、隐私和常见问题。

## 功能

- 显示累计听歌时长、听歌天数、最长连续和当前连续天数。
- 按天或按周显示年度及近一年热力图。
- 按小时、日期或每七天显示时长分布。
- 查看某个日期、小时或时段中的歌曲明细。
- 按歌曲、歌手或专辑查看播放次数排行。
- 按歌曲、歌手或专辑查看累计实际收听时长排行。
- 搜索排行内容并分页浏览。
- 导入、导出和合并本地备份。
- 跟随 SPW 的浅色、深色、椒盐经典、亚克力、云母和云母 Alt 外观。

插件不会提供独立窗口，也不会创建云端账户或同步服务。统计页通过宿主内容层嵌入 SPW 页面。

## 安装与打开

1. 从本地构建产物或 GitHub Releases 获取 .spmod 文件。
2. 在 SPW 的模组管理中执行本地导入。
3. 授权并启用 library-read 和 class-transform 权限。
4. 点击窗口顶部的听歌统计入口，或在模组配置中选择“打开听歌统计”。

插件不需要额外安装运行环境。安装文件通常位于：

~~~~text
%APPDATA%\Salt Player for Windows\workshop\plugins\
~~~~

展开目录名称会带有包版本，例如：

~~~~text
SPW-Stats-v0.3.3-dev.4\
~~~~

## 权限说明

| 权限 | 用途 |
|---|---|
| library-read | 读取宿主本地曲库和听歌历史数据库。 |
| class-transform | 在宿主页面、导航、标题栏和材质内容层注册 Hook，使统计页嵌入原生界面。 |

插件不申请 library-write，不会向宿主曲库写入统计结果，也不会修改 spw.db。

## 数据从哪里来

插件显示的结果不是单一的官方统计值，而是三类本地数据合并后的结果：

~~~~text
SPW 本地历史 + 插件实时记录 + 导入备份
→ 会话合并与去重
→ 日／小时聚合、播放次数和排行
~~~~

### 宿主本地历史

宿主数据库通常位于：

~~~~text
%APPDATA%\Salt Player for Windows\spw.db
~~~~

插件以只读方式读取 Listen 和 Track 表。

Listen 表读取：

| 字段 | 用途 |
|---|---|
| id | 宿主听歌记录的身份。 |
| trackId | 对应歌曲的身份。 |
| startTime | 开始时间，毫秒时间戳。 |
| duration | 宿主记录的收听时长，毫秒。 |

Track 表读取：

| 字段 | 用途 |
|---|---|
| id | 歌曲身份。 |
| title | 歌曲名。 |
| artist | 歌手字段。 |
| album | 专辑名。 |
| albumArtist | 专辑艺术家字段。 |
| duration | 歌曲总时长。 |
| path | 源音频文件路径，用于判断文件是否仍存在；旧宿主表没有此字段时保持未知。 |

插件只查询历史实际引用的歌曲元数据，不会把整张曲库无条件复制到插件目录。宿主数据库的保留范围、表结构和宿主自身记录方式会影响结果。

当前实现使用普通 SQLite JDBC 只读连接，没有在插件中加入 SQLCipher 或其他解密层。数据库不是插件加密格式；插件自己的 JSON 数据和备份也不是加密格式。备份校验和用于检查完整性，不用于保密。

### 插件实时记录

播放回调会记录插件启用后观察到的实际收听片段，保存为：

~~~~text
%APPDATA%\Salt Player for Windows\workshop\data\com.jethuit.spw.listenstats\live-sessions.json
~~~~

实时记录用于补充宿主汇总无法表达的暂停、拖动、跨日和跨小时片段。插件没有公开的当前播放状态查询，因此插件中途启用时只能在观察到稳定的曲目身份和合理前进的进度后开始记录，不会可靠补回启用之前的时间。

### 导入备份

导入后的合并数据保存在：

~~~~text
%APPDATA%\Salt Player for Windows\workshop\data\com.jethuit.spw.listenstats\imported.json
~~~~

新备份格式包含会话身份、来源曲库身份、收听片段和歌曲元数据。旧版 v1 汇总没有完整会话身份，导入时按小时和每首歌曲次数取较大值进行保守合并，可能少计重叠日期中的不同收听，不能当作精确去重。

备份读取有保护限制：文件最大 32 MB，v2 会话数量和单个片段数组数量均有上限。文件校验失败、结构不合法或读取过程中发生变化时，原有导入文件会保留。

## 统计口径

### 实际收听时长

- 使用实际观察到的播放片段计算。
- 暂停、停止和拖动跳过的时间不自动补入。
- 跨自然日或小时的片段会拆分到对应日期和小时。
- 同一会话的重叠片段会合并，避免重复累计。
- 宿主较长的近似汇总不会覆盖已知精确片段的位置；缺失差额只会分配到宿主区间中尚未覆盖的部分。

### 有效播放次数

同一次播放实际收听达到歌曲总时长的 50% 才计为一次有效播放。暂停和拖动跳过的时间不计入实际收听时长，因此不能仅凭进度跳转直接增加播放次数。

歌曲、歌手和专辑排行共用有效播放次数，但不展示跨榜单的全局播放次数。合作歌曲会分别计入每位歌手。

### 歌曲身份与元数据

同名歌曲不会仅按歌名合并。插件优先使用当前曲库中有效的歌曲字段，其次使用本机实时信息，历史备份只补充缺失字段。不同曲库来源的歌曲身份保持隔离；重建曲库、跨设备或曲库 ID 改变后，旧记录可能无法自动对应。

宿主曲库提供源文件路径时，统计刷新会检查文件是否仍是普通文件；已删除的源文件会从统计视图中隐藏，但不会删除宿主数据库、实时记录或备份。旧版记录没有路径时保留，因为无法安全判定文件是否已删除。

### 时长文字和热力图

- 最终合计时长一次性按分钟四舍五入，不逐片段取整。
- 余数不足 30 秒舍去，达到 30 秒进位。
- 热力图颜色按最近 12 个月的非零日时长或自然周时长分别计算四分位阈值。
- 颜色阈值只影响显示，不改变原始时长、播放次数或图表坐标。

## 页面和配置

统计页分为“听歌概览”和“听歌排行”。普通数据刷新会保留筛选、滚动位置和已打开的页面状态。

| 配置 | 默认值 | 说明 |
|---|---:|---|
| 页面刷新间隔 | 5 秒 | 可设置为 2～60 秒的整数。 |
| 排行每页数量 | 25 | 正整数设置；当前实现没有额外的最大值限制。 |
| 明细可见行数 | 6 | 可设置为 3～12 行。 |
| 页面动画 | 开启 | 控制整页、内部页面、排行切换和菜单动画。 |
| 显示明细操作提示 | 开启 | 控制图表下方的提示文字。 |
| 热力图展开动画 | 开启 | 控制热力格逐列出现的动画。 |

排行计算和搜索在后台调度器执行。搜索输入会短暂防抖；刷新时会保留上一份已完成的排行结果，避免页面先清空再重新出现。

## 数据目录和文件

插件数据目录为：

~~~~text
C:\Users\<用户名>\AppData\Roaming\Salt Player for Windows\workshop\data\com.jethuit.spw.listenstats\
~~~~

| 文件 | 说明 |
|---|---|
| live-sessions.json | 实时播放会话和收听片段。 |
| imported.json | 导入并合并后的备份事件。 |
| imported.previous.json | 导入新内容前保留的旧导入文件。 |
| source-id.txt | 本机曲库来源身份。 |
| source-id.backup.txt | 来源身份的冗余副本。 |
| status.log | 插件启动、宿主结构发现、权限和诊断状态。 |

宿主配置由 WorkshopApi 的 ConfigHelper 管理，具体配置文件位置由 SPW 决定，不应假定一定就在上述目录中。

## 隐私和安全边界

- 插件读取的是本机数据，不提供云同步。
- spw.db 由播放器拥有，插件只读，不写入或删除。
- 插件不会读取账号密码、登录令牌或音频文件。
- 插件数据和备份是普通 JSON 文件，不加密；能访问当前 Windows 用户目录的程序也可能读取它们。
- 备份校验和能发现文件被修改，但不能防止他人查看内容。
- 备份导出前应确认目标路径和文件权限，分享备份前应检查其中的歌曲标题、歌手、时间、收听记录和源文件路径。

## 卸载、重装和更新

### 卸载后数据为什么还在

插件安装文件和用户数据是分开的：

~~~~text
workshop\plugins\SPW-Stats-...\
workshop\data\com.jethuit.spw.listenstats\
~~~~

当前插件的删除回调不会主动清理自定义数据目录。因此删除并重新安装插件后，插件仍会读取原来的实时记录、导入备份和宿主 spw.db 历史。

SPW 删除对话框中的“同时删除此模组的用户数据”主要由宿主管理；它不应被当作清理插件自定义 JSON 数据的可靠保证。

### 真正清空插件数据

先导出备份，再关闭 SPW。要清空插件自己的统计数据，删除：

~~~~text
%APPDATA%\Salt Player for Windows\workshop\data\com.jethuit.spw.listenstats\
~~~~

不要为了清理插件而删除：

~~~~text
%APPDATA%\Salt Player for Windows\spw.db
~~~~

该文件包含整个播放器的本地历史。

### 当前版本的更新限制

在当前 SPW 1.19.2 环境中，直接点击插件管理器的更新按钮时，宿主会尝试在同一个 SPW 进程内移动已加载插件目录到 update-*/previous。即使插件收到 stop，宿主仍可能持有旧插件的 JAR 或 ClassLoader，导致目录移动失败并回滚到旧版本。

因此，当前可靠的开发包更新方式是：

1. 完全退出 SPW，并确认没有残留的 Salt Player for Windows 进程。
2. 关闭或删除旧插件安装目录，保留 workshop\data\com.jethuit.spw.listenstats\。
3. 启动 SPW 后导入新的 .spmod，或按宿主支持的启动时更新流程安装。

这属于宿主插件管理器的卸载／热替换限制，不是统计数据格式错误。插件无法从自身代码中卸载宿主持有的 ClassLoader。真实更新行为仍需按当前 SPW 安装环境验收。

## 常见问题

### 为什么重新安装后还能看到以前的数据？

因为宿主的 spw.db 和插件自己的 workshop\data\com.jethuit.spw.listenstats\ 都可能保留。重新安装后使用同一个插件 ID，会再次读取这些路径。

### 为什么数据库里的历史和插件实时记录不一定完全一致？

宿主历史是播放器保存的汇总记录，插件实时记录来自播放回调。两者的时间精度、保留范围和关联身份不同，插件会按会话身份和精确片段规则合并，不能保证恢复丢失的旧片段。

### 页面入口失效但听歌记录还在怎么办？

页面 Hook、标题栏入口和播放回调是相互独立的。宿主内部结构变化可能导致页面接入失败，但记录器仍可能继续保存实时记录。请在配置中写入诊断日志，并提供 status.log 内容和 SPW 版本。

### 如何判断当前运行的是哪个版本？

查看模组管理页面的版本号，或查看 status.log 中的：

~~~~text
start plugin <版本> for SPW <版本>
~~~~

如果更新失败后重新出现旧版本号，说明宿主更新器已经回滚。

## 诊断信息

配置页的“写入诊断日志”会把状态写入：

~~~~text
%APPDATA%\Salt Player for Windows\workshop\data\com.jethuit.spw.listenstats\status.log
~~~~

日志通常包含：

- 插件版本和 SPW 版本
- Java 和 Windows 版本
- 权限状态
- 数据目录和宿主数据库路径
- Hook 注册状态和宿主结构发现结果
- 实时记录存储错误

日志可能包含本机路径、版本、曲库来源身份和宿主结构信息，公开前应按需打码。


## 已知限制

- 宿主数据库保留范围和表结构变化可能影响历史读取。
- 插件不能可靠补回启用前的收听片段。
- 曲库重建、跨设备和歌曲身份变化可能导致旧记录无法对应。
- 公开播放 API 没有完整当前播放状态查询。
- 宿主页面结构、Compose、Workshop API 或字节码重新混淆后可能需要适配。
- AOT、真实 DWM 材质、窗口帧率和多插件共存仍需实机核对。
- 当前宿主插件更新器可能无法在同一进程内热替换已加载插件。
