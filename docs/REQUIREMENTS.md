# SPW-Listen Stats：正式模组需求

更新时间：2026-10-21。本文记录用户已确认的最终状态；早期截图与已撤回的设计不覆盖当前 `preview/`。原生模组后续新增需求以本文补充和最新交接为准。

## 目标与实现约束

为 Salt Player for Windows 制作“听歌统计”模组。正式前端完全按照当前示例的布局、文案、交互、图标与主题实现，优先原生 Kotlin / Compose / Salt UI。需要实际可安装的 `.spmod`，而不只是网页或 UI 演示。

用户已提供本机 SPW 安装目录供研究。主页内展示或入口曾被提出，仍需验证宿主扩展位置。无法按示例实现的部分须明确告知用户，并在有重大替代方案时询问，不静默改设计。

当前基准是 `preview/index.html`、`preview/styles.css`、`preview/app.js`。预览完成时的 Git 提交是 `4e25ed1`；后续原生实现以这组文件为视觉与交互依据。

## 统计与数据

- 记录真实听歌时长，并按本地自然日、小时保存；跨日或跨小时的时长需要正确拆分。
- 时长文字按分钟四舍五入：对最终合计时长一次舍入，余数不足 30 秒舍去，满 30 秒进位；不是每 30 秒计一分钟，也不逐片段舍入后再相加。提示、总时长及统计卡片共用，跨 60 分钟进位到小时；原始数据、图形高度、热力颜色档位与有效播放次数不受影响。
- 播放次数按每首歌曲独立累计；2026-10-20 用户新增歌手、专辑榜，按所含歌曲的有效播放次数求和，合作歌曲分别计入每位歌手。不展示跨榜单的全局总播放次数。
- 有效播放口径：同一次播放实际听满该歌曲时长的 50% 计一次。暂停和拖动跳过的进度不计入实际收听时长。
- 同名歌曲依歌曲身份分开，不能仅用歌名归并；曲库 ID 重建、跨设备等身份问题见可行性文档。
- 原生模组需要持久化统计，重启不丢失。预览目前只在内存中运行，刷新会恢复示例。
- 保留本地导入、导出入口。正式备份应有版本、校验及导入失败处理，不能直接把预览 JSON 当正式格式。
- 预览的日期、数字、歌曲和封面全是演示数据，正式模式不可默认显示为用户的真实记录；也不能凭已有曲库推算过去的收听历史。

2026-10-18 用户确认：同一遍播放按实际收听时间累计，拖回重听可累计，每遍最多计一次；暂停继续仍属同一遍，自动循环或重新从头播放开启下一遍。插件中途启用只记录观察到的收听片段；未知时长先记录时间，不猜测 50% 次数。

用户确认备份导入必须与本机合并并去重。新版使用会话身份；旧版 v1 无会话身份，用户同意兼容并明确提示可能少计，按小时和每首次数取较大值保守合并。不能把旧版汇总的保守合并宣称为精确去重。

## 页面结构与外观

- 顶部标题固定“听歌统计”，排行页也不改成“听歌排行”。标题下不再放副标题。
- “听歌概览 / 听歌排行”分为独立页面，导航字号 15px；切页保留当前筛选与数据。
- 2026-10-21：两项导航继续顶部横排，改成原生侧栏项风格：圆角浅底、常规字重。用户最终要求完全删除选中横条，仅用圆角底色与文字颜色区分当前页，取代此前左竖条和所有横条比例方案。深色实色选中底色 `#313232`，透明材质保留半透明填充，未选中项正常为透明；交互反馈色跟随主题。进入统计页整体轻微向上滑动淡入；概览/排行只让主体左右滑动淡入淡出，标题和导航固定，方向随切换方向反转。重复点击当前页不重播，快速反向切换不排队。
- 右上角只保留导入、导出。导入用 Google `download`，导出用 `upload`，使用离线 SVG。
- 2026-10-20 最新确认：删除插件深浅主题切换功能及按钮，始终跟随 SPW 宿主深浅主题。宿主明确选择的浅／深优先于操作系统；宿主跟随系统时才读取系统深浅色。旧插件主题偏好和启动主题覆盖不再生效，不提供手动模式。
- 以当前留白、细边框、蓝色强调色为准；浅深主题均需适配。原生字体渲染差异可以说明，不能据此擅自改变布局。
- 适配椒盐经典、亚克力、云母、云母 Alt；支持材质的嵌入入口继承宿主窗口背景，材质入口不可用时保留安全实色底。打开统计时不能透出底层歌曲列表，也不应清空原页面状态；真实 DWM 观感需实机验收。

- 2026-10-20 材质验收顺序：先按原版聚焦／失焦参考图校准亚克力的卡片、控件、分隔线和热力格颜色；云母、云母 Alt 随后逐个适配。本轮浅色参考不能作为深色亚克力已验收的证据。
- 2026-10-20 最新线条要求（取代此前保留底线、线色 `#B1B1B1` 的约定）：四种材质、浅深主题的概览与排行都删除灰色分隔线，包括标签栏下横线、排行表头／记录间／列表末尾线、概览页脚线及累计统计／听歌小结内部竖线；保留蓝色选中提示线。保持现有间距，卡片外框及图表坐标网格继续使用原样式。歌曲、歌手、专辑三种排行共用此结构。
- 2026-10-20 深色补充：按用户新提供的原版深色亚克力／云母截图校准卡片、控件、边框、文字和列表悬停色；保留透明页面、无分隔线及蓝色提示。先只改源码，不编译或构建，等下一轮云母 Alt 调整完再统一构建。

## 听歌概览

### 顶部累计统计

一个圆角边框内四列等宽，内容居中、列间细竖线：累计听歌时长、听歌天数、最长连续、当前连续。大数字、小单位。当前连续的预览逻辑：当天还没有听歌时，允许从昨天延续计算。

### 年度足迹

- 标题“年度足迹”，右侧“每天 / 每周”纯文字分组按钮及年份下拉，年份显示“2026年”这样的格式。
- 两个模式共用日历网格：从周一开始，七行；左侧保留“一、三、五、日”，月份在上方。
- 平年 365 个、闰年 366 个可见方格，年初、年末跨出该年的槽位都留空。每天与每周的数量、日期位置和大小一致。
- 方格圆角 **6px**；每日选中外框对应为 8px。保留悬停、焦点和选择效果。
- 每天颜色对应当天听歌时长。2026-10-20 用户确认新增模组配置项“每天听多久算多（小时）”，支持输入小数；默认 `2.25` 小时作为最高档门槛，其他分界为该值的 1/6 和 1/2。0 时长单独为 0 档，四个正时长档依次为不足 1/6、1/6 至不足 1/2、1/2 至不足完整值、达到完整值。默认分界是 22 分 30 秒／1 小时 7 分 30 秒／2 小时 15 分钟；输入 6 时对应 1／3／6 小时。
- 输入必须大于 0 且不超过 24 小时，无效值按默认值显示；由宿主原生输入控件保存配置，保存后重新打开或自动刷新时生效，不需要重新启用插件。只影响每日热力图颜色，不改真实时长、计次、排行榜、每周热力图或图表纵轴。
- 每周一列代表周一至周日的汇总，用最多七个自下而上的色块表示高度；高度相对本年单周峰值。颜色按该峰值的四个区间由浅到深，零时长为灰色。跨年周仅统计所选年份；当周只计到当天。
- 不显示热力图下方的说明、点击提示、缩放说明和“少—多”颜色图例。
- 每天提示：第一行“2026年9月14日”，第二行“听歌时长 2小时30分钟”。每周提示：第一行“2026年9月14日起的一周”，第二行“听歌时长 12小时18分钟”。全部左对齐，数值紧跟标签。
- 点击某天，联动下方该天的小时分布；点击某周，显示该周每天的时长。仍保留鼠标与键盘操作。

### 时长分布

- 标题“时长分布”，下方保留所选范围的听歌总时长说明。
- 支持柱状、折线、平滑曲线。三个切换按钮仅保留 Google 图标，悬停显示名称；默认折线图，记住本机选择。曲线保持单调插值，不超出相邻数据的极值。
- 日期范围包含近 7 天、近 30 天、本月、今天、热力图选中日期、自定义日期；日期框不带日历图标，保留下拉箭头。选日显示完整日期，自定义显示实际起止日期。
- 日期与粒度智能联动：单日固定显示 24 个小时区间；2～13 天固定按日；14 天及以上才显示“按日 / 按周”下拉。短范围自动选择不能覆盖长范围的粒度偏好。
- 周汇总沿用预览：从当前日期范围起点起，每七天一组，末组可不足七天；不要默默改成自然周。
- 所有横轴标签都居中对齐到对应柱子或数据点，首尾预留空间，窄屏减少标签。小时标签表示区间起点：00:00 对应 00:00–01:00，23:00 对应 23:00–24:00。稀疏标签之间的距离与真实时间跨度成比例。
- 纵轴按数据选择小时或分钟，刻度避免重复或错位。缩放后鼠标位置要正确转换，提示、柱子、曲线、标记使用同一坐标。
- 按日与按周有平均时长横虚线，平均值标在左侧纵轴，包含零收听时段；相邻普通刻度让位避免重叠。**单日按小时隐藏平均线**。
- 不显示图下重复日期范围、“悬停查看详情”，也不保留“查看图表数据”及其表格。

### 听歌小结

保留“听歌小结”标题，标题上方无横向分隔线。下方与顶部相同：一条圆角边框，三列等宽、居中、竖线分隔，每列仅两行：

| 列 | 第一行 | 第二行 |
| --- | --- | --- |
| 第一列 | 大数字、小单位的单日最高时长 | 听得最多 · 实际日期 |
| 第二列 | 大数字、小单位的平均收听时长 | 每日平均收听 |
| 第三列 | 常听小时区间，如 21:00 — 22:00 | 最常听歌时段 |

“每日平均收听”仍按有收听记录的日期计算；这与时长分布包含零值的范围平均线不同。常听时段按全部记录的小时累计计算。空数据显示真实空状态，不使用示例数填充。窄屏在同一外框内纵向排列。

## 听歌排行

- 单独页面，顶部主标题仍为“听歌统计”，内容标题随模式显示“歌曲播放次数 / 歌手播放次数 / 专辑播放次数”。
- 2026-10-20：搜索框左侧新增“歌曲 / 歌手 / 专辑”分组切换，复用现有“每天 / 每周”按钮风格。歌手和专辑汇总有效播放次数，合作歌曲分别计入每位歌手；切换回第一页，保留搜索文字和榜单模式偏好。
- 2026-10-20 后续确认：歌手榜以该歌手播放次数最高的专辑封面代替头像，按专辑内歌曲的有效播放次数合计选择。三榜列表参考原版适配：封面 48dp（截图 125% 下约 60px）、行距约 66dp，图文间距 12dp。
- 表格列为：排名、歌曲、专辑、播放次数。**排名表头和序号均居中**；次数靠右。
- 歌名左侧方形专辑封面，歌手在歌名下方。同专辑可共用封面，缺失或读取失败显示默认图。
- 默认固定按每首播放次数从高到低排列。不再提供歌名、歌手排序下拉；次数相同时按歌名中文次序，同名同次数保持原顺序。
- 支持歌名、歌手搜索，覆盖全体歌曲，保留榜单原排名；搜索和导入后回到第一页。
- **每页 50 首**。列表上、下方均提供页码与上一页／下一页，显示总数和当前范围，只渲染当前页；不足一页隐藏翻页。翻页后回到列表顶部。
- 底部一行说明：“每首歌独立累计 · 实际听满歌曲时长的 50% 计一次 · 不受概览页年份与日期筛选影响”。
- 三种排行都是累计数据，不随概览的年份、日期筛选变化。歌手和专辑榜按本次新增口径汇总，不额外显示跨榜单总次数。

## 完成标准

正式模组需要实际构建、安装并在本机 SPW 测试：启动／暂停／拖动／换曲的统计，50% 计次，跨小时／跨日分配，重启持久化，权限与空状态，真实封面，备份导入导出，页面入口及两种主题。预览回归检查不能代替宿主测试。不能实现或未经验证的项目必须在交付时列出，不宣称全部完成。
