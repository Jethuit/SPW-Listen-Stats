# 0.1.34 审查修复

日期：2026-10-19。修复来源见 [0.1.33 审查报告](BUG-REVIEW-0.1.33.md)。本版不改变分页外观和已确认的日历卡片样式。

## 修复内容

- **封面正常取消不再写失败冷却。** 以缓存层持有的协程任务合并相同曲目、相同尺寸请求；各行独立等待。取消发起行不会影响仍在等待的其他行；最后一个等待者离开后移除并取消任务，避免快速翻页留下无用排队。
- **清理后旧结果不能写回。** `clear()` 在同一锁下切换代际、清空状态，随后取消旧作用域。提交结果同时检查代际与当前请求身份；旧任务的完成回调不会移除同 key 的新请求。
- **真实失败仍保留 30 秒冷却。** 使用单调时钟，起算点改为失败完成时。API 取消不会被缓存为读取失败。
- **封面不再只重试一次。** 当前行存在且尚未加载成功时，每次失败后等待 30 秒再次加载；成功或离开组合后停止。确实没有内嵌封面的曲目继续显示占位图，最多按这个间隔查询。
- **日期弹窗键盘修复。** 初始焦点放在“取消”，遮罩不参与键盘聚焦；Esc 由弹窗内容的祖先处理；移除全局 Enter 确认，让取消、选日、翻月等控件处理自己的 Enter。“确定”在范围无效时使用组件的真正禁用状态。焦点组阻止键盘离开弹窗进入底层页面。
- **受限高度滚动。** 弹窗高度上限为当前可用高度减 32dp，内容使用纵向滚动；正常能完整放下时保留原布局，上下卡片时可滚动到日期与底部操作。

## 产物与待用户核对

产物路径：`build/libs/plugin-com.jethuit.spw.listenstats-0.1.34.spmod`。本轮不安装或启动播放器。

请在正常 SPW 中核对：

1. 快速翻页再返回，封面能重新加载；停留页面遇到暂时失败后仍能恢复。
2. 打开自定义日期后 Esc 关闭；重新打开后，聚焦取消、日期、翻月按钮时，Enter 执行各自操作。Tab／Shift+Tab 不进入底层页面。
3. 上下卡片或窗口高度不足时，滚动能到达两张日历和取消／确定按钮。正常高度下外观与原来一致。

键盘与视觉交互没有在宿主中实测，不能把构建和离线回归写成实机验收完成；真实图片解码、宿主帧率和长期内存也不在本轮验证范围。
