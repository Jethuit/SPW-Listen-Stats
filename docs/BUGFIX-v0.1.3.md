# v0.1.3 开发版修复

日期：2026-10-20。基于用户审查的 `main` / `139e1b082929568c4068281f004b4a897b78230c`，已快进同步其 README 修改。本轮不上传 GitHub，不改变 v0.1.2 Release，也不操作真实播放器数据。

## 四项修复

以下数据完整性修复已纳入 dev.1，dev.2 继续包含。

1. **生命周期片段重复累计**：允许同曲、近似相同播放起点且实际收听区间不重叠的片段对应同一宿主记录。将片段合并为一次播放，再与宿主快照比较完整程度，保留所有片段 ID 别名，使旧导出重导入仍可去重。
2. **旧位置配新歌曲**：在回调到达时捕获播放状态修订号、位置序号及此前已观察到的歌曲身份；后台查询完成后再次校验。过期队列、跨越状态变化、查询超时或前后歌曲身份不一致时丢弃该采样。首次身份观察只建立基线。
3. **元数据被较长的未知记录覆盖**：收听区间选择和歌曲信息合并分开处理。保留已知标题、歌手、专辑、专辑艺术家和正数曲长；聚合时还可从同一来源、同一歌曲的其他事件补齐信息，避免未知记录覆盖排行元数据。
4. **来源身份损坏破坏去重**：新增冗余身份文件和实时文件中的来源标记；主文件损坏时先恢复冗余身份，再尝试本地实时记录的标记或唯一宿主别名前缀。对于已被旧版本重新生成的身份，仅对能用歌曲与时间重新匹配的宿主记录迁移别名，并保留旧别名连接历史备份。运行中的旧会话副本回写不会把已迁移的别名覆盖回去。

新增的可选实时文件字段保持 `version: 2`，旧版记录仍可读取。来源身份恢复只参考本机实时存储，不从导入的其他曲库备份猜测本机身份。显式别名已连接本地宿主记录时，较长旧备份仍归入当前本地曲库。

## 能力边界

- 宿主 API 没有原子的“歌曲＋位置”快照。修复采用前后身份与回调序号校验，无法确认归属的采样会丢弃，因此启用或切歌边界可能少记一小段时间；不补猜这段时长。
- 宿主记录关联仍是近似起点匹配。多片段共享记录时额外要求起点差不超过 **250ms** 且实际区间不重叠，以避免将短间隔重播折叠。超出可靠条件的历史片段不强行归并。
- 主身份、冗余文件和本地实时记录都无法提供可恢复身份时，才生成新 UUID；未验证的历史关联不自动迁移。
- 这次没有对真实数据库或旧备份做批量改写；已发生且缺少可靠归属证据的旧采样不自动删除。
