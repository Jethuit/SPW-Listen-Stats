## 实现

- 系统主题通过宿主已包含的 Skiko `currentSystemTheme` 读取，删除每秒创建 `reg.exe` 的逻辑；宿主明确浅深选择继续优先。保留原有约 1 秒外观刷新。
- 宿主原始行、实时会话与导入事件先合并，再统一分桶一次，之后叠加 v1 保守下界。数据库继续每轮读取，不引入可能忽略 WAL 的文件时间缓存。直接调用 `HostDatabase.load()` 仍默认返回聚合结果；统计加载明确使用原始行模式。
- 导入备份按绝对路径、文件修改时间、大小和文件身份缓存已校验内容；读取前后确认文件未变化。插件导入成功后主动失效缓存；读取错误仍显示错误并保留文件。
- v1 元数据按字段补全：本地有效标签优先，占位标题、空字段和未知时长可用备份补齐。小时和次数仍取较大值，不宣称精确合并旧版汇总。
- 备份文件选择仍在 UI 线程，合并、编码、校验和文件读写移至 IO 线程；同页备份操作串行保护。页面偏好由单一后台写线程按回调顺序保存，保存前仍重新加载宿主配置，避免覆盖外部设置。字体增加单项缓存，含自定义文件修改时间和大小。
- 无滚动空间的末页不再触发“保持贴底”。切换日期预设、手动确认自定义范围会清除热力图旧选择；周选择联动保留。自定义下拉展示实际起止日期；日历年份覆盖历史、当前选择和已翻到的月份。边缘周的选中/悬停框只包含有效日期，空槽不触发整周悬停。
- 成功返回空封面的 API 结果缓存 5 分钟，异常保持 30 秒冷却；负缓存最多 512 项，过期允许恢复。已知外库命名空间 ID 不调用本机封面 API。专辑/歌手封面在原获胜组内优先使用本地曲目，不改变专辑分组和最高播放次数专辑的选择规则。
- 诊断按钮后台输出插件/SPW/Java/系统版本、时区、权限、数据/数据库路径、来源身份、Hook 注册情况、采样器状态和存储错误。不输出歌名或历史明细。日志跟随插件数据目录，失败时尝试临时目录；提示真实写入路径，写入失败不再提示成功。Hook 注册信息不等于宿主已成功完成字节码转换。
- Manifest 按 UTF-8 字节折行，每行正文最多 70 字节、续行含前导空格，保持 CRLF。新增展开还原检查；包结构检查也约束行长。本次仅验证编译与生成函数，既有发布包未重打。

## 播放身份与保留的限制

- 计时基线与曲尾证据分开。Buffering/Ready 导致基线失效后，仍可识别短时间内的明显曲尾回绕；显式 seek 清除回绕证据，非零回拖仍属同一遍。根据回调间隔设置有限窗口，要求大幅回落，不靠累计听够时长猜测重播。
- 进度差校验允许最多约 4 倍墙钟推进，仍只累计单调时钟经过的时间；长于 3 秒的单次计时空档继续丢弃，不补计休眠或无观测时间。
- 同歌曲身份已知时，状态切换后的首个有效回调可建立新基线，下一个有效回调开始累计，不跨越暂停/状态变化计时。首次换曲仍保留连续身份确认：API 不提供原子歌曲+位置快照，不能保证补回首次观察前的时间。排队回调、晚到查询和短暂 A→B→A 的隔离继续保留。
- 在开头或已观察到换曲时保留额外起点证据，写入实时文件可选 `observedOrigin` 字段。宿主首次匹配使用此证据，旧文件回退原估算；不扩大原 10 秒窗口，仍保留下一遍播放排除和错误别名清理。插件中途启用、未观察到起点且已经暂停/拖动的历史，仍不能可靠反推，不按同曲名强行合并。
- 不自动重写旧版已吞并的循环历史。不将无 `albumArtist` 的同名专辑按共同歌手猜测归并；不增加跨刷新数据库缓存，也未新增关闭统计页后的全部浏览状态保留。
- 本轮不修复宿主的自附加 Agent 路径兼容性问题，不把 Manifest 折行当成此前 Hook 安装失败的原因。
