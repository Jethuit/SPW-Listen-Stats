# 0.1.35 API 取消后的封面自动重试

日期：2026-10-19。对应 [0.1.34 复审](BUG-REVIEW-0.1.34.md) 的 P2 问题。

## 修改

`CoverStore.fetchAndDecode()` 捕获异常时检查当前协程的有效状态，而不只按异常类型决定是否向上传播。

- 当前协程仍有效、仅宿主 API future 自己取消时，返回 `null`，沿用暂时读取失败的 30 秒冷却，排行行的加载协程可继续进入等待和重试。
- 真实调用方取消、最后一个等待者离开，以及 clear 引发的取消仍传播；不把这些正常退出写成读取失败。

本版 API 取消会进入失败冷却，这与 0.1.34 让其直接取消任务的行为不同。0.1.34 的说明及测试只验证了可以手动立即重载；本次调整为与页面 30 秒自动重试一致，避免 API 取消反复发生时密集请求。

修复没有改变日期弹窗、分页或数据统计逻辑。

## 回归检查
