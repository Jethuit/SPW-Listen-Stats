## 发现

### 1. [P2] 正常取消封面加载会触发失败冷却

位置：`plugin/src/main/kotlin/com/jethuit/spw/listenstats/data/CoverStore.kt:75–78`。

**证据：隔离运行已复现。** 模拟 `getCoverById` 返回未完成的 future，等待请求进入 API 后取消协程，再立即调用同一曲目的 `load()`。两次加载的 API 调用总数仍为 **1**，第二次直接返回 `null`。

原因是 `fetchAndDecode()` 虽然重抛 `CancellationException`，`load()` 的外层 `catch (Throwable)` 又把它当成读取失败，写入 `failedAt` 并把共享 promise 完成为 `null`。冷却配置为 30 秒，起算点是请求开始时间。

触发条件：封面尚未加载完就翻页、离开排行或改变筛选，导致对应 `LaunchedEffect` 被取消；随后重新回到这些曲目。用户会继续看到占位图，通常要等接近 30 秒才能再次请求；这不是 API 实际返回的读取失败。

修复方向：单独处理并传播协程取消，不写失败冷却；同时正确清理共享请求，避免其他等待者把发起者的取消当成无封面结果。

### 2. [P2] 日期弹窗的键盘处理挂载位置错误

位置：`plugin/src/main/kotlin/com/jethuit/spw/listenstats/ui/DateRangeDialog.kt:89–110`，初始焦点请求位于第 85 行。

**证据：源码确认，宿主交互未实测。** 这里存在两种具体影响：

- 打开弹窗时，`rootFocus` 请求的是遮罩 `Surface` 的焦点；处理 Esc 的 `onPreviewKeyEvent` 位于遮罩的兄弟 `Box`。初始焦点落到遮罩后，Esc 不经过兄弟节点，因而不能触发这里的关闭处理。
- 焦点进入卡片内部后，该 `Box` 又会在预览阶段无条件消费 Enter 并调用 `submit()`。例如 Tab 聚焦“取消”再按 Enter，在日期范围有效时会执行确认；聚焦日期格或翻月按钮时，Enter 也会被抢走，不能执行当前控件的操作。

建议复核步骤：打开弹窗后直接按 Esc；重新打开后用 Tab 聚焦“取消”、日期格、上下月按钮，分别按 Enter。预期依次为关闭、取消、选日和翻月。

修复方向：把关闭键处理放在实际焦点路径的共同祖先，并将初始焦点放在弹窗内容内；让已聚焦的子控件优先处理 Enter，避免全局确认覆盖取消或选日操作。

### 3. [P2] 封面第二次加载失败后不再自动恢复

位置：`plugin/src/main/kotlin/com/jethuit/spw/listenstats/ui/RankingPage.kt:303–315`。

**证据：源码确认，未额外等待 30 秒运行 UI。** 只有 `image == null && retry == 0` 时才会延迟并递增 `retry`。因此每次组件存续期间最多加载两次；第二次仍失败后，即使 API 稍后恢复，继续停留当前页面也不会再次请求。

触发条件：首次加载失败，约 30 秒后的第二次请求也失败，之后临时故障解除。当前行会一直显示占位图，直到组件重新进入组合或歌曲 ID／目标像素尺寸变化。`HANDOFF.md` 中“自身每 30 秒重试”的表述比实际实现更强。

修复方向：明确并实现暂时失败后的恢复机制，例如有间隔的后续重试或可触发的刷新；对确实没有内嵌封面的曲目应保留合理的冷却与请求上限。

## 已核实的底层行为，但暂不单列为宿主 Bug

### clear 后旧封面请求仍能重建失败状态

位置：`CoverStore.kt:85–90`；生命周期调用在 `MainPlugin.kt:45–56`。

**隔离运行已复现：** 请求进入 API 后调用 `clear()`，再让旧 API 请求返回 `null`，随后立即重新加载同一首歌。API 总调用数仍为 **1**：旧请求在清空之后重新写入了失败冷却。

`clear()` 不作废 `inflight`，也没有代际校验。当前 `stop()` 中还通过 `SwingUtilities.invokeLater` 安排宿主页关闭，未等待组合取消完成，因此存在相关时序窗口。不过本轮没有验证宿主停用／重新启用是否复用同一个插件类加载器，也没有实测完整停用顺序，不能据此宣称真实重启一定显示旧缓存、发生内存泄漏或跨实例污染。

后续若修复生命周期，应让旧请求不能在清理后重新提交结果，例如使用代际标记并协调请求取消。此项可以和发现 1 一起处理。

## 待用户核对的布局风险

位置：`DateRangeDialog.kt:129–142`、第 175 行起的上下卡片分支，以及 `MonthGrid()` 的六周固定网格。

当卡片容器宽度不足 560dp 或 `fontScale > 1.15` 时，两张卡片上下排列，但内容列没有纵向滚动，也没有按可用高度调整的路径。受限高度下，下方日历、摘要或“取消／确定”存在被挤压、裁切或无法到达的风险。

本轮未运行窗口布局，未确定实际触发的窗口高度／DPI 阈值，因此这项保留为风险，不写成已实机复现。用户可在上下卡片状态缩短可用高度，核对两个日期网格和底部按钮是否完整、可点击。普通 DPI 缩放不必然等同于 `fontScale` 增大。
