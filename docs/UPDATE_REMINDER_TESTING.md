# 更新提醒实机演示

演示包 `0.3.5-dev.9.update-demo` 用于查看关于按钮蓝点、宿主实际轻提示和关于弹窗；它模拟 GitHub 返回正式版 `0.3.5`，不代表已经发布新版，也不验证 GitHub 网络连接。恢复使用的正常包为 `0.3.5-dev.10`。

## 操作

1. 在 SPW 模组管理中导入并启用 `SPW-Stats-v0.3.5-dev.9.update-demo.spmod`。
2. 打开听歌统计右上角“关于（更新演示）”，开启“为微软商店版启用更新提醒”，然后关闭弹窗。
3. 等待自动轻提示：首次模拟检查在启用约 10 秒后，之后每 5 秒检查一次。应出现“[更新演示] 听歌统计有新正式版本 0.3.5，可在‘关于’中查看。”的宿主成功轻提示；同一次启用期间只主动提示一次，统计页右上角“关于”按钮同时出现蓝点。
4. 再打开关于弹窗，检查右侧蓝色“有可用更新”和实际检查时间。打开并关闭关于后，按钮蓝点应继续显示。“检查更新”也返回模拟结果；“查看发布页”打开项目真实发布列表，不打开虚构的版本页面。
5. 完成后导入正常包 `SPW-Stats-v0.3.5-dev.10.spmod`。它恢复真实 GitHub 检查和正常频率。

演示缓存为系统临时目录下的 `spw-listenstats-update-demo-<随机 ID>.json`，不会改写正常更新缓存 `update-check.json`；每次重新启用演示包可再次查看自动提示。提醒开关仍使用原有配置，切回正常包后保留选择。统计业务代码保持原样。

## 构建

在项目根目录执行：

```powershell
py -3.12 tests/build-update-reminder-demo.py
```

脚本只在 `build/tests/update-demo-<版本>/` 中修改复制的源码，分别构建正常包和演示包到 `build/libs/`，不安装、不上传。演示包在模组名称、关于标题、版本和轻提示中均有标记。

演示包将自动检查间隔缩短为 5 秒，便于反复查看；正常包仍是启用约 30 秒后调度、距上次尝试至少 24 小时才联网。后续再次构建须使用新的演示版本和编号更高的正常开发版本；脚本拒绝覆盖已有安装包和已有演示构建目录。
