# v0.1.4-dev.1 统计修复

日期：2026-10-20。基于用户对 v0.1.3 / `b0db42a` 的两项 P2 审查报告，使用隔离目录和模拟宿主 API 复现并修复。此包供本地验收，当前公开版本仍为 v0.1.3。

## 修复内容

1. **短暂切歌把两次播放合并**：后台查询通过生命周期、回调序号和过期校验后，先独立处理已观察到的歌曲变化，结束旧歌曲会话；随后再判断位置是否可信。B 只观察一次、没有可接受的位置时也能结束旧 A，返回 A 后创建新的播放。未知歌曲或查询失败仍只重置采样，不据此判定切歌。
2. **连续合并丢失本地身份**：已确认本地事件的主 ID 和别名均参与宿主身份检查。即使更长的实时片段或旧备份成为主 ID，也保留已确认的本地曲库身份。单独出现的外部事件不会仅凭一个看似本地的别名自动转为本地。

没有修改备份格式、宿主数据库或统计计次门槛，也没有修改页面。

## 验证

- 在修改正式源码之前，对 v0.1.3 编译产物运行新增反例，原有 9 组完整性检查通过、新增 2 组失败：快速 A→B→A 实时 1 次 / 4,805ms，宿主同步后 7,206ms；140 秒宿主＋150 秒实时，导入 160 秒旧身份备份后本地计数为 0，再播放后出现两行。
- 新增反例在 `tests/DataIntegrityRegressionTest.kt`，涵盖 B 仅观察一次且不创建 B 播放、两次 A 的计次和宿主同步，以及旧备份连续合并、导出重导入、继续播放后的身份与行数。
- 修复后集中验证：39 文件构建成功，数据回归 **18/18**、完整性回归 **11/11**、排行回归 **7/7**，共 **36/36** 通过（原 34 组＋新增 2 组）。新反例确认两次 A 分别计次、宿主同步前后总时长一致；旧备份导入后仍属本地曲库，继续播放计为 2 次且只有一行歌曲。
- 包结构检查通过：157 项、17,233,781 字节，权限仍仅为 `library-read,class-transform`。测试使用模拟宿主 API，未运行真实 SPW 播放，未操作真实历史、数据库或备份。
- 能力边界：依然依赖宿主实际可观察到的歌曲信息；若 A→B→A 完全发生在两次有效观察之间，没有任何 B 的可靠信息，不能凭空推断该切歌。不会自动拆分已经被旧版合并、且缺少可靠分界的历史片段。

本地验收包：`build/libs/SPW-Stats-v0.1.4-dev.1.spmod`。
